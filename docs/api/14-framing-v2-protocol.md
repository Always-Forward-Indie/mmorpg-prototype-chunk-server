# 14. Фрейминг v2: length-prefix вместо `\n` (S14, ЗАВЕРШЕНО)

## Зачем
v1 (`\n`-разделитель + кап 8КБ + молчаливый дроп + `frag` opt-in из
середины handshake) — инверсия ответственности: транспорт обязан доставить,
а не отправитель угадать размер. Класс багов S13 (гонка флага, pre-ready
дропы, поллинг вместо resync) — следствие дизайна, а не кода. v2 убирает
класс: границы сообщений задаёт длина, кап превращается в DoS-guard с
явной ошибкой, capability не нужна вовсе.

## Формат кадра v2 (все сокеты, все три сервера)
```
[u32 LE длина N][N байт UTF-8 JSON]
```
- N = длина тела в БАЙТАХ (после UTF-8 кодирования), без учёта префикса.
- Порядок байт: little-endian, явно. Тело — тот же JSON-конверт
  (`header`/`body`), сериализаторы не меняются.
- `\n` в v2 не используется ни как разделитель, ни как терминатор.
- Лимит кадра: **4 МБ** (`kMaxFrameBytes`). Превышение = wire-ошибка
  (см. ниже), НЕ молча. Покрывает любой легитимный пакет с запасом
  (крупнейшие: снапшоты ~9КБ, каталог ~60КБ одним кадром).

## Определение режима (история; финал ниже)
На переходном этапе режим определялся по первым байтам (снуфинг v1/v2).
Финальное состояние (S14d): **клиентские сокеты — только v2**.
Не-v2 начало = фатальная ошибка кадра + разрыв (восстанавливается
штатным reconnect-механизмом). Исключение: game держит v2-чтение
с той же семантикой для всех (его chunk-линки шлют v1 — см. ниже).

## Server-to-server (game↔chunk) — отдельный транспорт, не тронут
Межсерверные линки ходят по `\n`-строкам без капа (свой ридер,
своя отправка, без wireFrag). У них никогда не было проблемы,
которую решает v2 (нет 8КБ-капа, нет дропов, факты идут через
outbox с exactly-once). Переводить их на v2 — отдельная работа
с отдельным риском (затрагивает docs/13), не часть S14.

## Согласование версий
Отдельного hello-раундтрипа нет: кадр либо валиден, либо рвёт соединение.
Клиент заявляет `framing: [2]` в теле join/auth (информационно, задел
под v3); сервер отвечает `framing: 2` в join/auth-ответе.
`frag:true` удалён везде (не отправляется, не парсится).

## Пути ошибок (единообразно, обе стороны)
| Случай | Действие |
|---|---|
| L > 4МБ | Error-уровень, счётчик, разрыв сокета (DoS-guard). Сервер: best-effort `ERR_OVERSIZE` + close. Клиент: `FNetFraming` возвращает -1 → разрыв через существующий drop/reconnect-механизм. |
| Обрыв mid-frame (EOF до 4+N байт) | Молчаливый дроп хвоста + разрыв. Счётчик. |
| Не-JSON после префикса | `ERR_MALFORMED`, БЕЗ разрыва (processMessage отвечает ошибкой, сессия живёт). Счётчик. |

## Что сделано (S14d)
- **chunk**: v2-only чтение и запись; удалены `\n`-ветка, wireFrag (pack/unpack/reassemble), `fragCapable`, `set/getClientFragCapable`, `chunkJsonArray`, v1-тесты. `wireStats.fragStreams/fragFrames` оставлены нулевыми ради совместимости формата.
- **game**: dual-read сохранён (chunk-линки v1), v1-send сохранён для них же; v2-путь для клиентов. Флага `frag` не было и нет.
- **login**: v2-only (пиров, кроме клиентов, нет).
- **UE**: v2-only отправка и приём (`ExtractFramedMessages`, префикс вместо `\n`), `framing:[2]` во все join/auth, v1-код и v1-спеки удалены.
- **python** (`mmo_proto.py`): v2 pack/unpack, `FragReassembler` удалён, боты шлют `framing:[2]`, контрактные тесты переписаны под v2.
- Греп-гейт: `wireFrag|fragCapable|parseFragOptIn|chunkJsonArray|packWireMessage|FragReassembler|isClientFragCapable|setSocketFramingV2` пуст везде, кроме исторических комментариев. Исключение: game держит dual-read (`wirev2::sniffFraming` + v1-ветка) ради chunk-линков — это задокументированный остаток, не клиентский путь.

## Матрица тестов
- Unit (обе стороны, byte-level): кадр по кускам через Recv (1-байтовые
  подачи), сплит-кодпоинт на границе чанков, склейка N кадров в одном
  Recv, L>4МБ → ошибка+разрыв, мусор вместо JSON → ошибка без разрыва.
- Live (DEV): login с жирным инвентарём (первый снапшот целым, 0 дропов),
